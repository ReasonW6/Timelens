# Timelens V1 决策地图

Tracker: local-markdown
Status: complete
Canonical path: docs/wayfinder/timelens-v1/map.md

## Destination

形成一份可直接交付开发的 Timelens V1 产品与技术规格：窗口时间模型、交互原型、采集与权限架构、数据与 AI 边界、性能验证方式均已决定，不再遗留会阻止实施的产品或架构问题。

## Notes

- 本地图只规划和消除决策，不直接实现正式应用。它及其链接票据、研究、合同和验证记录是 V1 规格的权威入口。
- 每次会话按需要使用 `grilling`、`domain-modeling`、`research` 与 `prototype`。
- V1 面向公开发布的单用户、本机优先、64 位 Windows 11 应用；首个可运行里程碑先覆盖窗口追踪、输入统计、时间轴和清理，快照与 AI 随后接入。
- Timelens 只把用户窗口建模为活动对象；辅助进程不展示、不计时。允许内部使用所属主进程作为托盘连续性的传感信号。
- 同一应用的多个窗口归入堆叠卡片并可展开；其时间取区间并集。一个时间轴区间可同时包含多个应用状态，但区间本身只计算一次。
- 只保留应用名称、路径与图标；不采集窗口标题、网址、页面或文档内容、OCR、剪贴板、原始按键序列。
- 输入按分钟、前台应用和按键/鼠标按钮聚合；快照默认每 5 分钟截取活动显示器并压缩为最长边 1280 像素的 WebP。
- 自动清理从最旧数据开始，先快照后明细；累计总数不自动删除，一键清空可删除全部数据但保留设置。
- AI 使用用户自备密钥的多提供商接口，覆盖 OpenAI 兼容及 Claude、Gemini 原生协议；确定性本地报告与 AI 总结相互独立，支持每日、固定间隔和手动时间段总结。
- 安装时一次 UAC 授权，窄职责采集器以最高权限登录启动；UI、报告和 AI 网络代码保持普通权限，日常不重复弹 UAC。
- 性能目标：空闲平均 CPU 不高于 0.5%，正常采集平均 CPU 不高于 1%，常驻内存不高于 100 MB，安装包不高于 20 MB（不计系统 WebView），非截图数据 30 天不高于 100 MB。

## Decisions so far

- 提权启动采用安装时一次授权注册最高权限登录任务：窄职责采集器提权，UI 与 AI 网络代码保持普通权限，服务留待确有登录前或跨会话需求时再引入。([票据](issues/02-validate-elevated-startup.md))
- Rust 原生、Tauri 2 与 WinUI 3/.NET 均可覆盖功能面，现有官方证据不能证明资源目标，最终基础方案须由同功能样机统一实测后决定。([研究票 03](issues/03-compare-lightweight-foundations.md))
- 窗口观测采用 WinEvent 增量、公开状态查询与低频对账；进程只作已出现窗口应用的内部归组/托盘传感器，分屏可见集合、虚拟桌面切换和跨进程托盘延续必须由原型校准。([研究票 01](issues/01-verify-windows-window-observability.md))
- [定义重叠窗口的前台与后台时间](issues/04-define-overlapping-window-time.md)：以可重叠的“显示中”、唯一的“聚焦中”和“后台”描述应用状态，所有统计基于现实区间并集而非应用或窗口数量累加。
- [核验 Windows 快照采集边界](issues/13-research-windows-snapshot-boundaries.md)：可靠快照限于已解锁交互会话的显示器合成画面；锁屏、安全桌面与断开会话跳过，捕获方案及轻量预算须由原型实测。
- [定义应用归组与托盘会话连续性](issues/05-define-application-grouping-and-tray-continuity.md)：应用按明确 Windows 身份或路径保守归组，用户可合并历史；窗口实例仅含可独立切换的顶层窗口，托盘延续只跟随原主应用而不猜跨进程移交。
- [定义快照与窗口状态的边界](issues/11-define-snapshot-state-boundaries.md)：快照以固定时间槽静默截取活动屏或逐屏截取；系统状态与独立截图排除名单决定缺失，图片仅可经逐张预览后的单次授权进入手动 AI 总结。
- [构建同功能架构样机并统一测量](issues/14-build-comparable-architecture-spikes.md)：V1 应用与 UI 基础确定为 Rust + windows-rs + Slint；本机三次交错 60 秒运行中，它是唯一同时满足 100 MB 峰值工作集和 20 MB 安装包目标的候选。三项 WPR 跟踪的状态、字节数和 SHA-256 已保留，体积巨大的 ETL 原文件未进入 Git。
- [选择采集器、界面与存储架构](issues/06-choose-collector-ui-storage-architecture.md)：普通 Slint 核心独占 SQLite 和 UI，提权采集器以有界缓冲经受限命名管道送入事实记录；无代码签名时不安装提权更新代理，每次升级由用户主动运行安装器并授权。
- [原型验证堆叠卡片时间轴与中键截取](issues/07-prototype-stacked-timeline.md)：V1 锁定顶部区间时间轴、左侧时段应用和中间应用状态详情的信息架构；正式 Slint UI 另做视觉设计，不照搬原型外观。
- [定义数据、清理与隐私合同](issues/08-define-data-retention-and-privacy-contract.md)：本地加密权威事实、持久化报告、独立排除名单、匿名永久总数、可见缺失、自动清理、便携备份及无静默丢失的迁移恢复边界均已锁定。
- [定义 AI 总结任务合同](issues/09-define-ai-summary-job-contract.md)：多供应商与可选模型、每日/间隔/手动调度、本地分支对话、可编辑提示词、流式推理展示、重试版本和快照能力边界均已锁定。
- [校准窗口状态分类器](issues/12-calibrate-window-state-classifier.md)：V1 锁定结构候选、用户窗口 onboarding、已追踪状态三层分类；WinEvent 只作增量触发，公开查询作事实源，启动/恢复/低频对账修复缺口。隐藏消息窗不建会话，显式窗口 AUMID 可跨路径归组，完全隐藏后的采集器重启必须由核心回种已知活动会话。
- [验证性能与安装体积预算](issues/10-validate-performance-and-packaging-budgets.md)：当前主机 Release 证据满足空闲/正常 CPU、100 MiB 常驻内存、20 MiB 安装包代理和 30 天 100 MiB 非截图数据预算；30 天合成库为 18.83 MiB，最终三进程安装器保守代理上界为 6.52 MiB。UI、观测器和核心重任务叠加的短时峰值为 111.32 MiB，因此重任务必须串行调度，最终签名 Inno 包及常驻/按需峰值仍是发布验收门槛。

## Not yet specified

- 无阻止 V1 开始实施的产品或架构决策缺口。

## Implementation milestones

1. **基础与权限边界**：建立 Rust workspace、Slint 外壳、可选安装路径的 Inno 安装器、一次 UAC 后的最高权限登录任务、受限命名管道、加密 SQLite 与可恢复迁移；以普通 UI、普通核心和窄职责提权采集器能稳定握手为验收。
2. **首个可运行闭环**：接入窗口分类器、托盘连续性、分钟输入聚合、应用泳道时间轴、详情展开、清理与一键清空；复跑三次 60 秒完整进程组性能，并以当前票 10 的预算作为硬门槛。
3. **快照与本地报告**：实现活动显示器定时快照、独立排除名单、缺失原因、预览/删除和确定性本地报告；验证锁屏、安全桌面、多显示器、存储上限和自动清理。
4. **AI 与分支对话**：实现 OpenAI 兼容、Claude、Gemini 和自定义提供商、模型能力标记、调度/手动总结、可编辑提示词、流式侧栏、重试版本和逐张授权视觉输入；网络代码保持普通权限，worker 按需退出。
5. **数据可携与发布硬化**：实现便携 ZIP 备份/恢复、凭据策略、签名更新、崩溃恢复和卸载清理；在干净 Windows 11 上完成最终 Inno 体积、权限、锁屏/睡眠/重启、30 天数据、常驻/按需资源及签名验收。

## Out of scope

- V1 不支持 macOS、Linux、多用户账号、团队管理、跨设备同步或云端数据托管。
- V1 不展示或统计辅助进程、CPU/内存占用、服务与纯托盘后台程序；只有曾产生受追踪窗口的应用可延续托盘后台会话。
- V1 不提供窗口标题、网址、内容识别、输入文本还原、剪贴板采集或原始输入事件查询。
- V1 不捆绑本地模型或平台付费 AI 额度。
- 本地图不包含正式应用代码的实现与发布。
