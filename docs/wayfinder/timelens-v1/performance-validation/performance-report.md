# Timelens V1 性能与体积预算本机验证

## 结论

Rust + windows-rs + Slint 方案仍可进入实现。当前主机证据满足已接受的空闲/正常 CPU、常驻内存、30 天非截图数据和 20 MiB 安装包预算，但有两个不能省略的发布门槛：最终 Inno Setup 安装器尚未生成；时间轴、30 天数据操作、快照和 AI 子进程叠加后的短时进程组峰值达到 **111.32 MiB**，因此重任务必须由核心串行调度，正式应用还要区分并复测“常驻”与“按需峰值”，不能把 111.32 MiB 写成低于 100 MiB。

本报告是用户批准的当前主机决策级验证，不是干净 VM 或签名发布候选验收。

## 预算判定

| 预算 | 本机结果 | 判定 |
| --- | ---: | --- |
| 空闲平均 CPU ≤ 0.5% | 已选 Slint 样机三次 60 秒稳态中位数 0.0141%；正式分类器 60 秒补测 0.0163% | 通过 |
| 正常采集平均 CPU ≤ 1% | 已选完整样机三次全程中位数 0.0745%，范围 0.0612–0.0805% | 通过 |
| 常驻内存 ≤ 100 MiB | 已选完整样机三次峰值工作集中位数 73.41 MiB，最大 73.45 MiB | 通过 |
| 安装包 ≤ 20 MiB | 已执行 IExpress 包 6.13 MiB；按最终三进程代理载荷保守上界 6.52 MiB | 决策通过，最终 Inno 包待复测 |
| 30 天非截图数据 ≤ 100 MiB | 19,742,720 字节，18.83 MiB；checkpoint 后 WAL/SHM 均为 0 | 通过 |

100 MiB 是地图中已经接受的“常驻内存”预算。`full-stack-peak` 故意让 Slint 时间轴、正式窗口观测器和核心压力套件重叠；套件依次完成建库、查询、输入聚合、快照编码，并在此前工作集尚未被操作系统回收时启动 AI 子进程。该场景峰值为 116,731,904 字节（111.32 MiB），平均 CPU 为 6.31%。它不是正常后台负载，也没有被标成通过，但证明正式核心必须避免并发执行历史大查询、快照编码和 AI 任务，并在 AI 子进程退出后释放缓存。

## 方法与数据规模

- 环境：Windows 11 Pro 64 位，build 26200；Ryzen 7 7840H，8 核 16 线程；14,731,603,968 字节物理内存；平衡电源计划；Rust/Cargo 1.94.1；主显示适配器报告 2560×1600。GDI 实际捕获的逻辑主屏为 1707×1067。
- 旧的已选架构基线保留三次交错 60 秒 Release 运行；本轮新增一次 60 秒正式 WinEvent 分类器观测、一次窗口突发、一次核心套件和一次全栈峰值重叠。
- 正常观测使用不可能匹配的类名前缀。观测器仍枚举并查询全桌面窗口，但输出只有 started/stopped 两行，不持久化用户当前应用路径。
- 30 天合成库包含 100 个应用、120,000 条应用状态区间、240,000 条窗口状态区间、43,200 条分钟输入汇总、7,680 条每日按键汇总、8,640 条快照元数据和 30 份约 8 KiB 的本地报告。每个应用还计入 16 KiB 合成图标。
- 快照只真实捕获并编码一帧，缩放为 1280×800 WebP；编码数据仅在内存中计数后释放，没有落盘保存屏幕像素。
- AI 使用同一 Release 可执行文件的本地 JSONL 流式 worker，不联网、不读取数据库内容、不调用真实供应商。

## 压力结果

### 窗口采集

- 正常 60 秒：平均 CPU 0.0163%，峰值工作集 31,232,000 字节（29.79 MiB），退出码 0。进程树包含测试二进制及其控制台宿主，因此该值是保守代理。
- 突发：透明夹具完成 500 轮创建、显示、最小化、恢复、隐藏和销毁，共 2,500 次显式状态操作，用时 27.78 秒；观测器生成 3,992 条记录、3,687,052 字节调试 JSONL。完整进程组平均 CPU 3.06%，峰值工作集 57,974,784 字节（55.29 MiB），两个根进程均正常退出。
- 突发 CPU 不适用 1% 正常采集预算。结果用于证明事件队列和窗口查询在约 90 次状态操作/秒下能有界完成，没有进程残留；正式采集器不得把逐事件调试 JSONL 写入生产路径。

最初的沙箱内采样因 WMI 进程树访问被拒绝，只产生不完整运行 `20260823-110653`。随后 2,500 轮夹具在 30 秒观测窗口内未完成，被测量器终止，对应运行 `20260823-110711`。500 轮版本 `20260823-111016` 完整通过，但尚无全栈峰值场景。这三次非主证据在迁移时删除；失败原因已记录，脚本也已加入“夹具必须自行完成”和“全栈套件必须产出指标”的硬校验。最终主证据为 `evidence/20260823-111353`。

### 输入聚合

5,000,000 个确定性合成按键/鼠标事件聚合到 256 个按键计数器和 3 个鼠标按钮计数器，保留状态仅 2,072 字节，Release 紧循环用时 6.60 ms。这个数字只证明聚合结构有界且计算余量充分，不代表 Windows 全局 hook、命名管道或真实输入注入的吞吐；正式应用仍须以回调只入有界缓冲、核心按分钟落库的方式实现。

### 历史查询

每项查询先预热一次，再执行 20 次并报告 p95：

| 查询 | 1 天 p95 | 7 天 p95 | 30 天 p95 |
| --- | ---: | ---: | ---: |
| 时间轴窗口区间，最多返回 50,000 行 | 26.51 ms | 34.71 ms | 19.56 ms |
| 应用状态汇总，返回 300 行 | 14.02 ms | 28.84 ms | 117.62 ms |
| 输入总数 | 0.10 ms | 0.73 ms | 3.30 ms |

30 天时间轴因命中 50,000 行上限而比 7 天更快，不能解释为全量读取更快。V1 必须保留可见范围虚拟化和分段加载；报告汇总可在后台串行执行，UI 线程不直接跑 30 天聚合。

### 快照与 AI

- 一次真实 GDI 捕获、缩放和 WebP 编码用时 73.23 ms，输出 90,692 字节；像素未持久化。本结果只覆盖当前 SDR 主屏单帧，不替代正式 Windows Graphics Capture、逐显示器、锁屏/安全桌面和连续定时验收。
- 本地 AI worker 流出 512 个 JSONL 分片、204,178 字节，用时 347.08 ms，退出码 0。它验证按需子进程、流式读取和有界生命周期，不验证 TLS、供应商限流、模型首 token 延迟、视觉上传或真实重试。

## 体积代理

最终架构的 Release 代理载荷由 Slint UI、同进程 AI worker 模式的核心、最高权限窗口观测器和随包 VC++ 运行库组成：

| 载荷 | 字节 |
| --- | ---: |
| Slint UI | 9,146,368 |
| 核心与 AI worker 代理 | 2,354,176 |
| 提权采集器代理 | 288,256 |
| app-local VC++ runtime | 173,824 |
| 安装后代理载荷合计 | 11,962,624（11.41 MiB） |

已实际构建并安装核验的 Slint IExpress 包为 6,422,528 字节。用未压缩的核心增量和采集器整体字节直接加到旧包，得到保守上界 6,834,688 字节（6.52 MiB），距离 20 MiB 预算还有 14,136,832 字节（13.48 MiB）。本机没有 `ISCC.exe`，所以这个值不能冒充最终 Inno Setup 大小；签名、卸载器、计划任务注册、可选安装路径资源和更新代理都必须计入发布候选。

所有研究二进制和 IExpress 安装器均未签名，不可发布。

## 锁定的实现约束与发布门槛

1. 正常窗口对账采用 30–60 秒周期；启动、解锁和恢复立即对账。WinEvent 回调只入有界队列，调试 JSONL 不进入生产版。
2. 输入只保留固定大小计数器和分钟桶；禁止把原始事件排队到数据库或日志。
3. 核心统一调度历史大查询、快照编码、清理/备份和 AI 任务，同一时刻只运行一个重任务。AI 子进程按请求创建，结束或取消后必须退出。
4. 时间轴只查询可见范围并分页/虚拟化；30 天应用汇总在后台执行并可取消。
5. 第一个正式可运行里程碑要在相同主机上复跑三次 60 秒普通采集，并把普通 UI、核心和提权采集器作为完整进程组采样。
6. 发布候选必须用最终 Inno Setup、签名二进制和真实可选安装路径重测安装包及安装后载荷；超过 20 MiB 不得静默放宽。
7. 发布候选必须用真实迁移后的 30 天数据库复核 100 MiB 非截图预算，并分别记录常驻峰值和快照/AI 按需峰值。若要求按需峰值也硬性不超过 100 MiB，需要重新评估 AI 子进程隔离或 UI 资源驻留，不能把本次 111.32 MiB 删除。

## 可复核性与限制

- `cargo fmt --check` 通过；`cargo test --release --offline` 通过，两个二进制当前没有单元测试，验收依赖端到端产物与退出码。
- 主证据目录是 [`evidence/20260823-111353`](evidence/20260823-111353)，汇总入口是 [`measurement-summary.json`](evidence/20260823-111353/measurement-summary.json)。
- Git 只保留汇总、进程采样和套件指标。19 MiB 可再生成的合成数据库、逐事件调试 JSONL、重复时间轴数据和截图像素均未保留；历史哈希见 [`local-evidence-manifest.txt`](local-evidence-manifest.txt)。
- 架构选型的三次正常基线来自 [`../spikes/evidence-report.md`](../spikes/evidence-report.md) 与 [`../spikes/benchmark-output/local-controlled-summary.json`](../spikes/benchmark-output/local-controlled-summary.json)。
- 当前主机不是干净 VM；缓存、其他前台应用、控制台宿主和显示缩放都会影响结果。最终发布验收仍需在干净 Windows 11 环境重跑。
- 本夹具没有调用真实 AI、没有上传数据，也没有保存截图像素。
