# Timelens 里程碑 2 实现与验收报告

日期：2026-08-24

## 结论

里程碑 2 已完成并通过当前 Windows 11 宿主机验收。32 MiB 持久断线缓冲、托盘连续性、分钟输入聚合、应用泳道时间轴与详情、保留策略及一键清空均已进入正式 workspace。三轮完整进程组性能、30 天非图片数据、隐私不变量和 Release 体积均低于既定硬门槛。

按项目当前决定，Windows 11 虚拟机验收被明确跳过；两个 Release 可执行文件均保持 `NotSigned`，未把签名列为门禁。

## 实现范围

- 协议升级至 v3，加入分钟输入、托盘状态和显式监控缺口，所有帧、批次、字段及键位集合均有固定上限和严格校验。
- Collector 使用固定 33,554,432 字节的加密持久缓冲。记录先落盘并同步，再切换双槽校验头；只有核心持久化后返回的精确 ACK 才删除最旧批次。溢出不丢最旧记录，改为新 run、显式缺口和最新窗口/托盘快照。
- 低级输入钩子忽略注入事件和键盘自动重复，只保留物理扫描码、键盘布局及左/中/右键计数；原始事件只在内存聚合，跨分钟后写入分钟桶、每日键位频率和匿名累计账本。
- 托盘后台仅在同一 PID 与进程创建时间仍存活且最后一个合格窗口消失时推断，并以加密状态跨 Collector 重启恢复。
- Slint UI 提供 6 小时、24 小时、7 天范围，应用泳道、打开/显示/聚焦/后台指标、时间轴片段、输入计数、缺口提示和编号窗口展开；中键拖选区间换算覆盖正反方向、边界裁剪及最小宽度。
- SQLCipher schema v8 提供窗口、输入、托盘、可用性与保留模型。7/30/90 天及永久策略可立即清理；一键清空协调 Collector 暂停，删除产品数据、轮换数据库与缓冲密钥，再恢复最新快照。

## 发现并解决的问题

首次正式 30 天负载暴露出 `window_state_intervals` 当前状态查找缺少部分索引，每次状态更新会扫描增长中的历史表，复杂度退化为近似 O(n²)。schema v8 增加 `one_open_state_per_window_instance` 及时间轴查询索引，并由 `EXPLAIN QUERY PLAN` 测试锁定命中。相同的 100 应用、240,000 次状态更新和 43,200 个输入分钟负载随后在 10.290 秒完成。

最终输入审计还发现两个边缘条件：采样在分钟边界附近可能被归入下一分钟，低级钩子与排空线程争用时也可能静默跳过事件。输入样本现携带钩子发生时的 UTC 分钟；争用会清除按键按下状态并生成显式 `InputOverflow` 缺口。对应边界、自动重复和争用恢复均有单元测试。

## 验收结果

### 自动化与实时闭环

- `cargo fmt --all -- --check`：通过。
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`：通过，零 warning。
- `cargo test --workspace --release`：55 项通过，0 失败。
- Collector 离线缓冲：核心离线时 4 批；Collector 重启后 5 批且 DPAPI 密钥文件哈希不变；核心启动并精确 ACK 后为 0 批。
- Collector 清空协调：真实进程创建 paused 标记、轮换缓冲密钥、移除 paused 标记并继续运行；在线与离线数据库清空、设置保留及数据库密钥轮换另由存储测试覆盖。
- UI：真实采集数据下显示 5 个应用和 2 个明确缺口；6 小时、24 小时、7 天切换、泳道、指标、输入、时间轴以及窗口 1/2/3 展开与滚动均正常，1120×720 无裁切。为避免自动化直接执行本地删除，清理和清空按钮只做可见性复查，其行为由自动化与真实 Collector 协调测试覆盖。
