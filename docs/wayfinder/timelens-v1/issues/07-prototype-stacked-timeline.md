# 原型验证堆叠卡片时间轴与中键截取

Type: prototype
Status: resolved
Blocked by: 04, 05, 06

## Question

用低成本可交互原型验证：同一时间段包含多个应用状态时怎样展示；同一应用多个无标题窗口怎样堆叠、编号并展开；应用更新路径变化后怎样人工合并历史；用户怎样拖动回溯历史；中键拖拽怎样选择时间段并立即打开确定性本地报告。原型必须由用户实际评审后才能决定交互方案。

## Comments

### 2026-08-22 可交互原型待用户评审

- [单文件时间轴原型](../prototypes/timeline-ui-prototype.html)提供 A“应用泳道”、B“现实时间流”和 C“区段胶片”三种结构，可用页面底部切换器、键盘左右键或 `?variant=A|B|C` 比较。
- 三种变体共享同一份应用、窗口和状态数据，均支持卡片展开、全天总览拖动、应用路径人工合并，以及中键拖拽后立即打开确定性本地报告。
- 浏览器 QA 已覆盖横向和纵向中键选择、历史回溯、展开、合并、URL 切换与窄窗口布局；JavaScript 无语法或控制台错误。
- 当前目录不是 Git 仓库，无法建立 throwaway 原型分支，因此暂以本地票据资产保留。票据等待用户实际选择后再解决。

- 用户选择 A“应用泳道”，并明确布局为：顶部时间轴负责中键截取，左侧只显示选中时段应用，中间显示当前应用的具体使用情况。

- 浏览器 QA 已验证顶栏中键截取、应用切换、多窗口展开、当前选区报告、900px 窄窗口以及零控制台错误。票据继续保持 `claimed`，等待用户实际确认精简版 A 后再解决。

## Answer

用户确认 A“应用泳道”的信息架构作为 V1 实施方向：顶部使用全天时间轴并只在这里进行中键区间截取，左侧列出选中时段内的应用，中间按当前选中应用显示打开、前台显示、获得焦点与后台时长，并允许展开同一应用的编号窗口实例。任意现实区间仍只计算一次，各应用状态可在该区间内重叠。

当前原型只锁定信息层级和交互关系，不锁定最终视觉设计。用户明确表示现有视觉布局仍不满意，正式 Slint UI 实施时应重新完成视觉设计，但不得因此改变上述已确认结构。确定性时段报告由中间详情显式打开，并沿用顶部当前选区；AI 总结继续作为独立功能。
