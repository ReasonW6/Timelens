# 只以任务栏窗口计时

Type: grilling
Status: resolved
Blocked by: 05, 12

## Question

用户反馈：关闭后缩到通知区域的应用（如 Steam）仍持续累计后台；Steam 被记成辅助进程 `steamwebhelper`；“开始”“搜索”等系统外壳面板被当作应用。应用何时算打开、何时算后台，是否仍保留票据 05 的“推断托盘后台”？

## Answer

只计任务栏上有按钮的窗口。显示、聚焦沿用原定义；后台只包括最小化（以及其他虚拟桌面、锁屏期间）仍留在任务栏的窗口。窗口隐藏到通知区域、变为工具窗口或在当前桌面被系统外壳隐身时，窗口实例随即结束（仅被应用自身隐身、或桌面归属查询失败时保留）；最后一个窗口结束后不再推断托盘后台。此结论取代票据 05 中“窗口隐藏计为后台”和“推断托盘后台”两条；升级前已开始的托盘后台区间照常在应用重新出现窗口或退出时结束，已有历史统计保持原样。

`Windows\SystemApps` 下系统进程的顶层 `Windows.UI.Core.CoreWindow` 是“开始”“搜索”、通知中心、触摸键盘、锁屏等外壳面板，不是窗口实例；其他应用的 CoreWindow 不受影响。

文件名以 `helper` 结尾的进程拥有的窗口，归属于从自身安装目录启动该辅助进程的上级程序（如 `Steam\bin\cef\…\steamwebhelper.exe` → `Steam\steam.exe`），身份与元数据取自上级程序；不满足该目录关系时保留辅助进程自身身份，避免把从库目录启动的游戏并入启动器。

聚焦是显示的子集：统计时聚焦区间一律计为显示（历史数据同样适用），因此聚焦时长不会超过显示时长；全屏游戏切回前台、窗口尚未恢复的短暂区间不再造成“聚焦大于显示”。最小化的前台窗口不算聚焦，此规则只作用于升级后的新记录。
