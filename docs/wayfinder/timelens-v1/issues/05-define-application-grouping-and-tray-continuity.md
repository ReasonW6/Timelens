# 定义应用归组与托盘会话连续性

Type: grilling
Status: resolved
Blocked by: 01

## Question

什么稳定身份把多个窗口归入同一应用卡片？一个应用拥有多个主窗口、子窗口、不同可执行文件或打包身份时如何处理？窗口隐藏或销毁但应用留在通知区域时，会话怎样继续并最终结束，同时保证从未产生用户窗口的辅助进程永不形成记录？

## Answer

应用归组采用保守的稳定身份顺序：优先使用显式 AppUserModelID 或包身份；没有明确身份时使用规范化可执行文件路径。显示名称、图标或发布者不能单独触发合并。不同路径只有在明确 Windows 身份相同或用户通过“与旧应用记录合并”确认后才共享历史；人工合并规则持久保存并可移除，禁止模糊静默合并。

窗口实例只包括可独立切换的用户顶层窗口。独立主窗口和可独立切换的设置窗口分别计数；模态对话框、菜单、下拉框、提示、浏览器或文档标签页均归属主窗口，不单独计数；从未产生用户窗口的辅助进程永不生成记录。由于不保存标题，展开项以会话内“窗口 1、窗口 2”编号区分，只显示允许的应用身份、打开时间、状态、各类时长、显示器和虚拟桌面信息。

第一个受追踪窗口出现时应用会话开始，后续窗口加入同一会话，各自记录实例区间，应用级时间取并集。窗口隐藏时会话明确继续并计为后台；最后一个窗口销毁但其原所属主应用仍存活时，以“推断托盘后台”继续，直到原主应用退出。该生存信号不产生进程卡片或进程活动记录。跨进程托盘移交不作猜测：原主应用退出即结束会话，新进程只有产生受追踪窗口后才开始新会话。对关闭窗口后长期保留无意义主进程的应用，允许设置“关闭最后窗口即结束记录”的应用级覆盖规则。
