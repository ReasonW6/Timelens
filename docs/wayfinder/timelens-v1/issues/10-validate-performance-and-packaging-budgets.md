# 验证性能与安装体积预算

Type: task
Status: resolved
Blocked by: 06, 07, 08, 12

## Question

建立最小测量夹具，验证已选架构在普通采集、窗口高频变化、输入高频、定时快照、历史查询和 AI 请求下的 CPU、内存、数据库增长与安装体积；记录硬件、数据规模和测量方法。若任何已接受预算不可达，提供事实以触发架构或产品取舍，而不是静默放宽指标。

## Resolution

已建立独立 Release 测量夹具并在用户批准的当前 Windows 11 主机完成普通窗口观测、透明窗口突发、固定内存输入聚合、30 天 SQLite 数据与查询、一次不落盘真实快照编码、本地流式 AI 子进程及全栈峰值重叠测量。

- 三次既有 Slint 正常基线与本轮分类器补测满足 0.5% 空闲、1% 正常 CPU 和 100 MiB 常驻内存预算；正常完整样机峰值工作集最大 73.45 MiB。
- 30 天非截图合成数据为 19,742,720 字节（18.83 MiB）。
- 已核验 IExpress 包为 6.13 MiB；按最终三进程代理载荷计算的保守安装器上界为 6.52 MiB。当前主机没有 Inno Setup，最终签名 Inno 安装器仍是发布门槛。
- 500 轮透明窗口夹具完成 2,500 次状态操作并正常退出；突发平均 CPU 3.06%，明确只作压力值，不套用正常采集预算。
- UI、观测器和核心重任务重叠时峰值工作集为 111.32 MiB。100 MiB 原预算明确是常驻预算，因此未静默放宽；实现必须串行调度重任务，并在发布候选分别复测常驻和按需峰值。若未来要求任何按需场景也不超过 100 MiB，则必须重开架构取舍。

完整方法、限制、发布门槛和证据见 [`../performance-validation/performance-report.md`](../performance-validation/performance-report.md)。
