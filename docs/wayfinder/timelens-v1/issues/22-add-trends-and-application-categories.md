# 新增统计趋势与应用分类

Type: grilling
Status: resolved
Blocked by: 08, 19

## Question

「统计」页只有所选时段的汇总和应用排行，看不出跨天的变化；应用也只能逐个查看，没法按用途汇总。要不要加入趋势视图和应用分类？它们和「不采集窗口标题、网址、内容」「未知数据不推测、不补齐」这两条约束是什么关系？

选宝的选择：新增「趋势」页签；内容包括按时间的柱状图、与上一周期的对比、一天中的时段分布；预设几个分类，可以改名和增删；归类方式是手动指定加上按安装目录自动归类。

## Answer

两者都只用已经记录的事实计算，不新增采集，也不改动协议。

### 趋势

趋势是 Projection，随统计页所选的时段变化。

- 统计页新增「趋势」页签，放在「应用」和「键位与系统」之间。
- **柱状图**：范围不超过 26 小时（含夏令时那天）时按本地小时分桶，不超过 92 天时按本地日期分桶，更长的范围按月分桶；每根柱子按分类堆叠聚焦时长。
- **与上一周期对比**：整天的范围往前平移相同天数；还在进行中的范围只比到上一周期的同一时刻；其他范围往前平移同样长度；「全部记录」不做对比。上一周期没有聚焦记录时只说明这一点，不给百分比。
- **一天中的分布**：多日范围下，各个钟点的日均聚焦时长，等于该钟点的聚焦总和除以范围涉及的天数。单日范围不显示，因为柱状图已经按小时分桶。
- 时长口径和「应用」页签的聚焦总计一致：同一应用的聚焦区间先取并集，合并的应用算作一个，系统组件不计。Monitoring gap 和没观察到的时间不补齐，柱子空着就是空着。

### 应用分类

- Application category 是用户给应用贴的标签，只依据 Application identity 和已记录的可执行文件路径，不看窗口标题或内容。
- 一个应用最多属于一个分类，合并的应用共用同一个分类。
- 升级到 schema v17 时预设工作、学习、娱乐、社交、工具五个分类。预设分类的名称跟随界面语言，改名后固定显示用户起的名字。分类可以改名、新建和删除。所有应用起初都是「按目录自动」。
- 归类优先级：手动指定（包括明确选择「未分类」）高于目录规则，目录规则高于未分类。多个目录都匹配时，最长的那个胜出。目录规则对已有的和以后出现的应用都生效，在显示时计算，不写进应用记录。
- 一个目录只能属于一个分类。删除分类后，手动指定到它的应用回到「按目录自动」。
- 分类、目录规则和手动指定都保存在加密数据集里，随便携备份一起恢复；一键清空时和应用规则一样保留；删除某个应用的全部历史时，一并删除它的手动指定。

不做：

- 按窗口标题、网址或内容分类，或自动猜测常见应用属于哪个分类。
- 多层分类、按分类设置排除规则。
- 在 JSON / CSV 导出中加入分类（留待以后单独决定）。
