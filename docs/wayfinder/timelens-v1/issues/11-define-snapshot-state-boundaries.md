# 定义快照与窗口状态的边界

Type: grilling
Status: resolved
Blocked by: 05, 13

## Question

在多个应用同时显示、唯一应用聚焦、跨显示器、桌面空闲、锁屏、睡眠、安全桌面、排除应用和全局暂停等状态下，定时快照应截取哪个显示器、何时跳过、怎样在时间轴中留下缺失原因，并允许哪些快照元数据进入本地报告或经明确授权进入 AI 总结？

## Comments

### 2026-08-22 第一轮确认

- 默认每 5 分钟截取活动显示器，可选 1、3、5、10、15、30 或 60 分钟，也可切换为所有显示器逐屏生成独立图片。活动显示器依次由聚焦窗口最大相交面积、鼠标所在显示器和主显示器确定。
- 调度采用固定时间槽；修改间隔后重启周期，任何跳过或失败都不补拍。桌面空闲、全局暂停、锁屏、睡眠、UAC 安全桌面、会话断开和捕获失败只形成缺失原因，不生成图片；不绕过 DRM 或应用防捕获。
- 静默是硬性边界：不得显示选择器、通知、闪烁或持续捕获边框。优先验证 Desktop Duplication；WGC 仅可在一次授权后无持续边框运行时作为备选，拒绝或不支持时禁用快照且不重复打扰。
- V1 在远程会话中默认跳过快照，窗口与输入统计继续；只有通过支持矩阵的远程环境才能以后开放。
- AI 默认不接收图片。手动总结可逐张预览并取消后授予单次快照授权；定时总结禁止携带快照。Timelens 不做 OCR，但发送前必须告知远端模型可能识别图中文字。

## Answer

快照按固定时间槽生成。默认每 5 分钟截取活动显示器，可选 1、3、5、10、15、30 或 60 分钟，也可逐屏截取所有显示器。活动显示器依次由聚焦窗口最大相交面积、鼠标所在显示器和主显示器确定；跨屏截图不拼接。修改周期后重新计时，跳过或失败均不补拍。

桌面空闲、全局暂停、锁屏、睡眠、UAC 安全桌面、Windows 会话断开和捕获失败只形成快照缺失记录。V1 远程会话默认跳过图片；受保护内容允许黑块或缺失且不得绕过。捕获必须静默，不得显示选择器、通知、闪烁或持续边框；优先验证 Desktop Duplication，WGC 只有在一次授权后能无持续边框运行时才可备选，否则禁用快照且不重复提示。

截图使用独立的“截图排除应用列表”，不与时间轴排除名单同步，也不改变时间轴记录或输入归属。排除应用显示在目标屏幕时跳过该屏，所有显示器模式下不影响其他屏幕；最小化、托盘或其他虚拟桌面中的排除应用不触发跳过。Timelens 默认正常进入时间轴和快照，首次引导只询问是否把 Timelens 加入截图排除列表。

每个时间槽保留成功图片或标准缺失原因；连续相同原因只在界面合并，底层仍保留次数，隐私排除原因不记录触发应用名称，被清理的图片明确标为已清理。图片外部保存为 SDR WebP，不嵌入 EXIF 或文本；SQLite 只索引时间槽、显示器内部身份与几何、像素尺寸、字节数、哈希、触发方式、捕获方法、结果及时间轴关联。

像素完全相同的图片文件可按哈希去重，但各时间槽保留独立引用；不做感知相似去重。快照包含鼠标指针以及实际可见的系统通知和叠加层，不识别或模糊其中内容，HDR 必须色调映射为 SDR。AI 默认不接收图片；手动总结只有在用户逐张预览并授予单次授权后，才能发送所选图片、捕获时间以及当时显示中和聚焦中的应用名称，禁止发送路径、显示器硬件身份、排除规则，定时总结永不携带图片。
