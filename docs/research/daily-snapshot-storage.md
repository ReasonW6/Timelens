# 按本地自然日保存快照

仅改变本地图片存储和配套迁移。拍摄入口、频率、WebP 编码、质量、预览、单张删除入口和设置界面保持原样。

## 文件与索引

- schema 13 在原有槽和全局像素去重表之外新增容器、容器记录、槽日期三张表，不重写其他业务表。
- 有图片的每个本地自然日只有一个 `snapshots/<随机 32 位十六进制>.tlsday` 文件。文件名不暴露日期、应用或图片哈希。
- 文件头为 8 字节 `TLSDAY\0\x01`，后面依次追加独立的 AES-256-GCM 图片记录。每条记录沿用经过验证的 CNG 加密实现，使用系统随机生成的独立 256 位密钥、96 位 nonce 和 128 位认证标签。
- 本地日期、偏移、长度、每条记录的密钥和原始 WebP 的 SHA-256 全部保存在 SQLCipher 数据库中。图片像素哈希继续作为认证附加数据。读取只访问对应记录并检查认证标签、编码字节哈希、大小和像素哈希。
- 同一天相同像素继续共用一条记录，快照槽仍各自独立。跨天相同图片各保存一条独立加密记录，因此删除旧日不会使新日失效。兼容原有备份和 AI 图片授权使用的全局 blob ID。
- 新图片使用捕获 UTC 时间转换到系统本地自然日，首次写入后固定日期；时区后来改变时不重新归属。每天可以为 23、24 或 25 小时。

## 提交与异常恢复

1. 在数据库即时事务中锁定索引，用 `synchronous=FULL` 提交快照变更。其他采集写入保留原来的同步设置。
2. 追加密文并刷新文件，回读实际文件、认证并核对原 WebP 字节，再提交偏移、长度、密钥和槽引用。
3. 文件的 `committed_bytes` 以数据库为准。事务未提交的尾部可在下一次追加或启动时截断，已提交的图片不受影响。
4. 文件被截断、头部或索引损坏时保留原件并报错，不把损坏的容器当作成功迁移。已有文件缺失沿用明确的 `capture_failed` 记录。
5. 替换文件始终使用新随机文件名。提交前旧文件为权威；提交后新文件为权威。COMMIT 返回 I/O 错误时保留两边文件，重启以后依据数据库结果清理，避免猜测提交是否生效。
6. 只回收格式严格匹配且没有引用的 Timelens 图片文件，不遍历删除其他目录或无关文件。重解析点不作为图片文件读取或删除。

## 单张删除、隐私与空间

- 删除一个槽不会删除同日其他槽仍引用的相同图片，沿用原有去重语义。
- 当天最后一个引用删除后，用新的文件只复制当天仍保留的认证密文记录，刷新并回读验证。原有图片不重新编码。
- 同一数据库事务删除被删记录的密钥，更新剩余记录位置并切换新文件。`secure_delete=ON` 清除数据库删除单元，确认 WAL 检查点完成并截断，然后删除旧容器。删除最后一张图片直接移除当天容器，不创建空文件。
- 删除成功后，软件管理的当前数据库、WAL 和图片目录不保留可恢复的旧图片或撤销副本。若删除提交后文件清理遇到错误，程序会报错，启动或下一次保留清理会继续回收无引用旧文件。
- 重建临时占用的空间最多为当天剩余图片的大小；临时写入或验证失败会保留原图与原引用，不扩大删除范围。整天清理不需要重建空间。
- 这是应用管理范围内的删除，不能承诺 SSD 闪存、文件系统/系统备份、页文件或用户外部导出文件的物理擦除。外部备份和导出仍由用户自行管理。

SQLite 的 [secure_delete](https://www.sqlite.org/pragma.html#pragma_secure_delete) 会覆盖删除内容；[WAL 检查点](https://www.sqlite.org/wal.html#checkpointing) 和截断用于移除旧日志页。SQLCipher 保护[数据库页和日志](https://www.zetetic.net/sqlcipher/design/)，不能将这些措施解释为存储设备的物理安全擦除。

## 保留与容量

- 保留 N 天包括今天及此前 N−1 个本地自然日。更早的日容器，从最早一天开始整体删除。
- 空间统计使用实际提交的容器字节数，包括头部和加密开销。超限时从最早一天整体删除，直到限额满足；不会留下部分日图片。
- 单个当前日也可能超过总限额，此时会清理这整天。之后的正常拍摄仍按原周期重新建立当天容器，不改变频率或画质。
- 被清理槽保留原有 `retention_cleaned` 结果和缺失说明；单张删除仍为 `user_deleted`。活动、输入、报告及 AI 保留策略不改变。

## 旧数据迁移、备份与恢复

1. 原有加密数据库增量升级沿用临时加密安全副本和事务回滚。
2. 先固定所有旧槽的日期，再按天提交图片迁移。旧格式未记录捕获时的时区，所以首次迁移按当前系统时区对历史 UTC 时间的规则划分日期，包含该时区的夏令时规则；无法反推出用户过去曾使用的其他时区。
3. 旧 `.tlsnap` 认证解密，直接将原 WebP 字节用新独立密钥加密追加。每条在落盘后回读并逐字节比较。每个槽的 ID、时间、显示器和全局去重引用保持不变。
4. 全部槽均有新的索引、所有新记录完整验证并完成数据库检查点后，才删除旧文件。中断或失败保留全部旧文件；重启从缺少容器记录的位置继续，不重复添加已经提交的记录。损坏旧图片会停止迁移，不静默丢弃。
5. 便携 ZIP 仍导出原 WebP；不导出本机容器密钥和偏移。schema 12 等旧备份和新备份在加密暂存数据集中完成日容器迁移、校验后恢复。新备份保留已经固定的自然日归属。
6. 替换备份先复制并验证新日容器，再一次事务替换数据库；失败保留原数据。数据目录迁移验证每一天的每个去重记录，并在验证以后切换位置。恢复到新目录保留损坏原件。

## 回归验证

测试覆盖同日多图追加、原始编码字节、独立密钥、午夜和 23/25 小时日、整天时间与空间清理、跨天去重、单张删除后的真实文件缩小与密钥清除、追加/迁移/删除中断恢复、旧密文损坏、认证篡改、新旧便携备份、数据目录迁移和恢复。
