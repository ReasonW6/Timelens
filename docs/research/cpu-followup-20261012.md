# 保留内存优化的采集器 CPU 优化（2026-10-12）

先提交检查点 **d9b5f8473ed5aecbe9693c9f7bd96fb61d236870**，保存上一轮五项内存优化及报告。此轮只修改采集器的 main.rs 和 input_identity.rs，CPU 改动保留在工作区，未推送；其余 373 个原跟踪文件保持检查点哈希。

## 最终改动

- 窗口身份直接消费观察器已有的增量转换。焦点或显示状态改变但身份、进程创建时间不变时，复用原身份分配；只修改新增、关闭和身份变化的项。原有 30 秒全量核对仍执行，用来补齐漏事件。
- 只把关闭或身份变化的版本暂留至输入结算。识别句柄与 PID 复用，防止旧关闭事件移除新进程版本；同一结算内多次身份变化遵循所有候选身份的输入排除规则。结算后释放暂留表，窗口大量减少时回收过大的表容量。
- 输入身份与隐私归属每批、每个窗口解析一次；临时解析表在结算方法返回时释放。窗口表和输入桶共享不可变身份字符串，分钟消息序列化时再生成协议字符串；聚合桶使用一次树表查询。输入总数、物理键频、匿名计数、溢出上限和 IPC 协议保持一致。

12 MiB 图标预算、可见历史范围、共享统计和图片缓冲优化全部保留。当前 TimelineSeries 的追加只用于测试构造，SQL 查询的追加对象是临时 Vec，未测到该路径成为生产热点，因此本轮没有修改统计容器或像素算法。没有修改界面、键盘布局、拍摄频率、画质、数据库、加密、隐私删除或空间回收。
