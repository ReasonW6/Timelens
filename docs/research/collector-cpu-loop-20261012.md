# 采集器无效唤醒与状态复用优化

## 检查点和范围

开始修改前已提交 `6d54ba00585d711385a4424611a15f6bc5465023`（`perf: checkpoint collector CPU tuning and validation`），保存此前输入身份增量更新、共享输入桶和验证报告。没有推送远端。

本轮修改 `timelens-collector/src/event_wait.rs`、`main.rs`、`collection.rs` 及 `timelens-observer/src/lib.rs`。应用界面、统计存储、图标预算、历史缓存、拍摄处理、加密容器和删除实现均保留。没有使用 Computer Use。

## 实现

- 主循环一次计算绝对截止时间，仍取分钟结算、30 秒全量核对、最长 1 秒必要状态检查中的最早时点。消息泵唤醒但没有有效窗口事件时，继续等待这个截止时间；真实事件和全量核对请求立即返回。Windows 毫秒等待向上取整，避免截止前不足 1 毫秒时忙轮询。
- 观察器只在窗口或托盘发生语义变化时重建共享结果。未变结果使用同一 `Arc`；窗口当前观察值直接移入跟踪项，省去一次复制。托盘没有候选和关闭事件时跳过构建应用键集合；已有候选继续检查进程存活和窗口重现。
- 过滤器以共享结果的弱引用识别同一版本，避免额外保留旧窗口数据。未变结果复用过滤后的窗口、托盘及活动类型。规则变化、阻止状态变化、睡眠及时间不连续仍使缓存失效。系统区间与心跳检查每轮保留。加密托盘状态只在最终内容变化时保存。

这些冗余路径已确认存在，但不能据此认定此前 CPU 样本上涨由上一轮内存优化引入。

## 完整采集器受控对照

基线取检查点源代码，修改版取本轮源代码，使用相同 Rust 1.94.1 优化设置。每种负载交替运行 10 对，共 60 个独立采集器进程；每次重放 130 秒逻辑时间、64 个合成窗口。

执行完整生产采集循环、观察器跟踪与身份逻辑、隐私过滤、分钟聚合、DPAPI 加密 spool、交付线程及真实互认证命名管道确认。测试适配器只替换操作系统观察边界和时间源，输入为合成聚合样本；确认端代替 Core 数据库写入者。采集器与确认端使用隔离目录和管道，不安装真实输入钩子、不向桌面注入输入、不操作现有窗口或真实数据。
