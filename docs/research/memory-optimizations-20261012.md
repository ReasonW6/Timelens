# 五项内存优化与本机验证（2026-10-12）

改动前先提交检查点 **767592074b6d10eddffb9bf6939363f28c29dc79**，保存此前所有本地修复、加密图片容器和四项 CPU 优化。此次优化留在工作区，未推送。

## 最终实现

1. 统计快照使用共享所有权。已结束的窗口和分段保存在只读共享数组，活动尾部使用独立的小覆盖层；统计、历史和存储缓存传递共享引用，避免完整 TimelineSnapshot 深复制。共享机制见 [Rust Arc 文档](https://doc.rust-lang.org/std/sync/struct.Arc.html)。
2. 图标原图和 DPI 缩放图统一使用 **12 MiB** 的 LRU 像素预算，相同原图按内容去重并共享 DPI 变体，整组淘汰。保留 256 像素提取、原 Lanczos3 缩放、预乘透明度处理和高 DPI 尺寸计算；失效图标的重试行为保留。预算约束缓存持有的像素，界面仍引用的图像及渲染器资源另占内存。
3. 历史完整数据仅保留可见日期及前后两天、今天和选中项所在日期。远处保留键、行高、日期定位等轻量信息，后台分批加载。滚动使用原行高与绝对位置，日期锚点和选中项继续保留；搜索切换、日期跨天、数据清理使旧异步结果失效。原 HistoryRow 样式、行高、键盘布局和快照界面均保留。
4. 屏幕旋转直接把映射像素写入最终 RGBA 缓冲，省去中间整图。预览解码移动 RGBA 所有权，尽早释放加密容器解密得到的 WebP 临时数据。逐像素和编码回归验证尺寸、旋转、HDR 转换、透明度、缩放及 WebP 编码参数保持一致。
5. 采集器只长期保留当前窗口映射。关闭窗口的身份保留到相关输入样本结算，再释放；样本携带临时进程 ID 区分句柄复用。无法唯一归属时保留匿名计数，并遵循两端身份的输入排除规则，不猜测应用。原始按键序列仍不采集，进程 ID 不新增到持久协议或数据库。

没有新增配置、改变拍摄频率或画质，也没有修改数据库版本、快照加密、单图隐私删除、容器压缩回收与整天保留期清理。源码检查确认 359 个原跟踪文件保持检查点哈希，改动集中于 11 个既有文件及 4 个新内存模块。

Private Bytes 是进程私有提交量，工作集是当前驻留内存，包含共享页面。这轮私有提交量下降，工作集上升。表中的峰值是该采样区间的最大值，生命周期峰值另存，二者没有混用。背景采样没有大量翻阅历史或加载数百个真实应用图标；用户活动、进程运行时长、原生缓存和背景负载也会影响结果，因此这里只报告这台机器这两段实测，不作统一降幅保证。

这次生产进程 CPU 样本上升，不能据此声称 CPU 改善或已证明 CPU 无回退。追加的 30 秒新旧 Release 只读窗口观察同时自检，均得到 1 次触发、5 个打开窗口、0 次更新和关闭，CPU 时间为 0.09375 s → 0.0625 s。自检没有访问存储或离线队列，也没有重启正式进程。它只能说明这段共同的窗口观察负载没有显示耗时增加，不能代替完整生产采集器、输入归属和队列的性能结论；两段生产样本的 CPU 差异尚未完成因果归因。四项原 CPU 优化的隐藏/最小化门控、增量统计、截止时间等待和事件增量/定期核对机制保留，并有相关回归覆盖。
